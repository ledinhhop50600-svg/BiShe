## 一、视觉主题

原来的界面是 Element Plus 默认蓝 + 纯白卡片，功能没问题但观感普通。这一轮定了新的视觉基调：

| 元素 | 选择 |
|---|---|
| 底色 | 暖纸色 `#f6f1e8`，叠两层很淡的径向光 |
| 主色 | 深青 `#1f5a54`（按钮、标题线、主图表） |
| 点缀 | 铜金 `#b08a5a`（编号、选中态左条、强调标签） |
| 正文 | 深墨 `#26312f`，次要文字 `#8b8174` |
| 标题 | 宋体/思源宋体（`--app-serif`），正文用苹方/微软雅黑 |
| 卡片 | 16px 圆角、1px 暖灰边、很轻的阴影，不用重投影 |

实现方式：`frontend/src/styles/theme.css` 覆盖 Element Plus 的 CSS 变量与少量组件样式，
页面自己的布局仍写在 `<style scoped>` 里。侧边栏改成深青渐变 + 铜金 logo 方块，
选中项用左侧金色细条；登录页改成左右分栏：左边品牌与三句价值主张，右边登录与演示账号。

## 二、可视化看板

数据接口：`GET /api/dashboard/overview`（`DashboardServiceImpl`），按角色返回：

- **卡片**：管理员（用户/稿件/待审/已发布）、审核员（待审/待举报/今日新增/今日已处理）、
  创作者（我的稿件/待审/已发布/被驳回）；
- **趋势**：近 14 天投稿与发布（14 天是为了让演示数据也能看出趋势，7 天可能全是 0）；
- **分布**：稿件状态、智能体风险等级、人工处理（采纳/改判/人工）、各平台适配次数；
- **最近动态**：最近 5 条智能体判定 + 最近 6 篇稿件；
- **脉搏**：智能体判定次数、适配次数、人工改判率。

前端用 ECharts（按需引入，`src/utils/echarts.js` + `ChartBox.vue`）画折线/环图/条形图，
配色与主题一致（深青、铜金、灰绿、陶土）。看板不重算指标，只负责展示，口径与后端一致。

## 四、性能基线（第一轮，优化前）

> 这一节是优化前的基线，保留用于对比；第二轮的内存四方向与速度实验结果见 `docs/性能与优化/性能优化实验.md`。

脚本：`python tools/perf_report.py`（需三端 + MySQL 在运行）。
产物：`docs/性能与优化/性能分析报告.md`、`docs/perf/perf-latest.json`、memory.png / latency.png / adapt.png。

### 内存（负载后）

| 进程 | RSS | Private | 说明 |
|---|---|---|---|
| 后端 SpringBoot | 209 MB | 269 MB | JVM 堆 40 MB、Metaspace 50 MB、59 个线程 |
| 智能体 Python | 74 MB | 58 MB | 解释器 + FastAPI/uvicorn + SDK，不加载本地模型 |
| 前端 Vite | 499 MB | 1435 MB | **开发服务器**；生产构建是静态文件，不需要 Node 常驻 |
| MySQL | 35 MB | 662 MB | WorkingSet 不含 buffer pool；以 Private 为准（Buffer Pool 128 MB） |

按 RSS 合计约 **817 MB**；把 MySQL 的 Private 计入、Vite 只算 RSS 时约 **1.4 GB**。
注意：RSS 含共享页，进程相加会略大于真实独占内存；Vite 的 Private 1.4 GB 是 Node 预留地址空间。

### 耗时

| 场景 | 总耗时 | 模型 | 后端/网络 |
|---|---|---|---|
| 登录（BCrypt + DB） | 198 ms | - | 全部 |
| 稿件列表（DB） | 87 ms | - | 全部 |
| 看板聚合（多次查询） | 53 ms | - | 全部 |
| 智能体预检 | 3.1 s | 3.08 s（98%） | 62 ms |
| 正式初审 | 5.0 s | 4.94 s（99%） | 54 ms |
| 适配 1 平台 | 3.4 s | 改写 1.97 s + 合规 1.37 s | 57 ms |
| 适配 3 平台 | 10.6 s | 改写 6.28 s + 合规 4.28 s（串行） | 86 ms |

结论：

1. **模型调用是绝对大头**（98% 以上）；检索/定位在缓存命中时几乎为 0；
2. 适配是串行的，3 个平台 ≈ 3 倍单平台；要快就按平台并行，而不是换数据库；
3. 常驻内存的大头是 MySQL（Private）和后端 JVM；智能体很轻；Vite 只是开发期；
4. 测量时开启了 MyBatis SQL 日志，之后已在 `application.properties` 中关闭，
   所以数据库接口现在会比报告里的 87 ms 更快。

## 五、环境变化与 start.bat

本机的 JDK17 / Maven 从 `E:\tools` 换到了 `F:\Dev\toolchains`。`start.bat` 顶部已加检测：

```bat
if exist "F:/Dev/toolchains/jdk17/bin/java.exe" (
    set "JAVA_HOME=F:/Dev/toolchains/jdk17"
    set "PATH=F:/Dev/toolchains/jdk17/bin;F:/Dev/toolchains/maven/bin;%PATH%"
)
```

换机器时改这两行，或把 `bin` 加进系统 PATH 即可。系统默认的 Java 8 跑不了 Spring Boot 4，
所以这一步必须保证。

## 八、第二轮：内存与速度专项

第二轮把“能不能降、降了有什么代价”做成了对照实验：

- **前端**：Vite dev 222.4 MB → production preview 98.1 MB（约 -56%），preview 已配 `/api` 代理；
- **后端**：小堆 + 串行 GC + Tomcat 20 / Hikari 5，应用 JVM 209.2 → 152.6–172.9 MB；
  另外发现 `mvn spring-boot:run` 的 Maven 父进程占 256.5 MB，打包后 `java -jar` 实测 204.3 MB，
  `start-low-memory.bat` 已改为优先跑 jar；
- **MySQL**：Private 664.4 MB，拆出 `performance_schema` 230.9 MB + Buffer Pool 130.8 MB；
  动态把 Buffer Pool 调到 64 MB 会被 128 MB 的 chunk 向上取整，chunk size 只读，必须改 `my.ini` 重启；
- **Agent**：75.1 MB，依赖只有 5 个包且不加载本地模型，惰性导入收益只有几 MB，未改；
- **速度**：并行适配是唯一稳定收益；合并一次调用、通用提示词都不划算；思考 none 5.6 s / 608 token，
  low/high 约 8.5 s / 1.1k token，判定等级相同，默认继续关思考。

完整数据、代价与复现命令见 `docs/性能与优化/性能优化实验.md` 与 `docs/性能与优化/实验-速度优化.md`。
