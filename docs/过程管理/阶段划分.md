# 阶段划分

> 按 [D-P3](../决策与选型/decisions-process.md) 的约定：**只表达依赖顺序与完成标准，不绑日历日期**。可以跳阶段，但必须满足「入口条件」。
> 每个阶段结束都必须产出两样东西：**可运行/可见的成果** + **开发笔记**。笔记里固定包含一节「本阶段你必须能讲出来的 3 件事」。
> 文档产出位置：过程文档写 `docs/`；对外交付版本整理进 `技术说明文档/` 与 `项目说明文档/`。

**全貌**：`0 骨架 → 1 数据库+登录 → 2 权限 → 3 内容管理 → 4 Agent 跑通 → 5 审核做准（含平台规则）→ 6 跨平台适配 → 7 人机闭环 → 8 评测实验 → 9 交付答辩`

**进度**：✅ 阶段 0 → ✅ 阶段 1 → ✅ 阶段 2 → ✅ 阶段 3 → ✅ 阶段 4 → 🟡 阶段 5（检索与对比实验已完成，评测集待做）
各阶段开发笔记见 `docs/开发笔记/`；数据库表结构见 [数据库设计文档.md](../设计文档/数据库设计文档.md)；阶段 0–2 的汇报材料见 [汇报文档-阶段0至2.md](../答辩材料/汇报文档-阶段0至2.md)；智能体契约见 [Agent接口契约-v1.md](../设计文档/Agent接口契约-v1.md)；对比实验见 [实验-对比实验-v1.md](../实验报告/实验-对比实验-v1.md)。

阶段 0–3 是「学校要求的管理系统」，阶段 4–8 是「创新点」。按用户意愿先做完前四段再碰 Agent；但阶段 1 就要把审核与平台相关的表建好，阶段 3 就要把接口契约定死 —— 这两处是防止创新点变成空壳的关键。

## 阶段 0：环境与骨架验证

- **目标**：先证明「这套技术栈在你机器上真的能跑通」，再写任何业务代码。**唯一一个"先验证后开发"的阶段，用来消化 Spring Boot 4.1.1 的版本风险。**
- **入口**：方案 A 已确定（见 `docs/决策与选型/decisions-stack.md`）。
- **做什么**：
  1. 把 Maven 本地仓库（`.m2`）与 npm 缓存从 C 盘迁到 E 盘（C 盘只剩 22G，不迁迟早爆盘）
  2. 配置 Maven 阿里云镜像、npm 走 npmmirror
  3. 用 start.spring.io 生成 Spring Boot 4.1.1 空项目（JDK 17 + Maven）
  4. 用 `create-vue` 生成 Vue 3 空项目，装 Element Plus
  5. Python 建 venv，起一个最小 FastAPI 服务，装 openai SDK
  6. MySQL 建库（utf8mb4）
  7. **打通最小链路**：前端一个按钮 → 后端接口 → 读一行 MySQL 数据 → 返回并显示
  8. 写一键启动 `.bat`
- **产出物**：三端可运行骨架 + 《环境搭建与踩坑记录》 + 一键启动脚本。
- **验收标准**：双击 `.bat`，浏览器打开页面点按钮，能看到**来自数据库**的数据；你能口头复述「这个请求经过了哪几层」。
- **决策点**：若 Spring Boot 4.1.1 遇到无法解决的生态摩擦 → **此时退回 3.5.16**（业务代码尚未开始，代价接近零），并记录进 `docs/决策与选型/decisions-stack.md`。

## 阶段 1：数据库设计与登录认证（地基）

- **入口**：阶段 0 验收通过。
- **做什么**：
  1. 表结构：用户、角色、菜单、用户-角色、角色-菜单、稿件、分类、标签、**审核记录**、**审核规则（含平台字段）**、**平台清单（含格式约束）**、举报、敏感词、**审核改判记录**、**适配记录**
  2. 画 ER 图、写 `schema.sql`、准备种子数据（三种角色的测试账号、平台清单、规则条目）
  3. 后端基础设施：统一响应体、全局异常处理、分页封装、参数校验
  4. 集成 Sa-Token：登录、登出、获取当前用户
  5. 前端：登录页 + 路由守卫 + Axios 拦截器
- **产出物**：数据库设计文档（ER 图 + 字段说明）+ `schema.sql` + 《登录认证实现说明》。
- **验收标准**：三种角色都能登录；未登录访问后台被弹回登录页；**每一张表你都能说出"它存的是什么"**。
- **硬约束**：按 D-A4，**审核记录、审核规则、平台清单三张表必须在本阶段建好**，不能等 Agent 阶段再加表。

## 阶段 2：RBAC 完整实现（用户 / 角色 / 菜单）

- **入口**：阶段 1。
- **做什么**：用户管理（列表/搜索/新增/编辑/禁用/重置密码）；角色管理（含分配菜单权限）；菜单管理（树形、排序、按钮级权限标识）；后端动态返回菜单树；前端动态菜单 + 按钮级权限指令。
- **产出物**：三个管理模块 + 《权限设计说明》（重点讲清「登录之后菜单是怎么来的」）。
- **验收标准**：审核员登录只看到审核相关菜单；管理员看到全部；无权限按钮不可见、直接调接口也被拒。

---

## 阶段 3：内容管理与平台清单（Agent 的输入对象）

- **入口**：阶段 2。
- **做什么**：
  1. 稿件管理：增删改查、分类标签、上下架
  2. **创作者投稿页**（极简前台）：写稿、存草稿、发布前检查入口、提交发布申请
  3. 稿件状态机：草稿 / 待审核 / 已发布 / 已驳回 / 已阻断 / 已下架
  4. **平台管理**（管理员）：平台清单维护、各平台格式约束与规则集的维护界面
  5. 举报处理
  6. 敏感词库维护 + 匹配逻辑（**论文对比基线**）
  7. **冻结《Agent 接口契约》**：本次升级为**两个接口** —— ①审核接口 ②适配接口（请求含目标平台集合，响应含各平台版本 + 格式自检结果 + 平台合规提示）
- **产出物**：内容管理 + 投稿页 + 平台管理 + 举报 + 敏感词基线 + **《Agent 接口契约 v1》**。
- **验收标准**：创作者能投稿并提交；审核员能看到待审列表；平台清单可维护；敏感词库能命中明显违规文本；契约冻结。
- **说明**：本阶段的审核动作先由「敏感词基线 + 人工审核」顶上，Agent 是**替换/增强**这个环节，不是新造流程 —— 即使 Agent 延期，系统也是完整的。

---

## 阶段 4：智能体服务骨架与模型接入

- **入口**：阶段 3（契约已冻结）。
- **做什么**：FastAPI 骨架（路由/配置/日志/健康检查）；模型 Provider 抽象（DeepSeek 主用 + 可降级）；openai SDK 接入并拿到结构化 JSON 输出；**响应回放模式**（缓存响应供测试与重复评测）；Java 侧调用客户端（超时、重试、失败降级到人工审核）。
- **产出物**：能返回朴素结论的 Agent 服务 + 《模型接入与降级说明》。
- **验收标准**：主系统提交稿件能拿到结构化结论；**手动停掉 Agent 服务后主系统不报错、优雅退回人工审核**。
- **注意**：只求「跑通」，不求「判得准」。

## 阶段 5：审核智能体核心（规则库 + RAG + 分级 + 建议）

- **入口**：阶段 4。
- **做什么**：
  1. **Agent 主循环**：工具选择 → 调用 → 取结果 → 继续判断 → 终止
  2. **工具注册表**：规则检索、稿件信息查询、作者历史查询
  3. **规则库构建（按平台维度组织）**：通用六类规则（广告法极限词 / 虚假宣传 / 低俗擦边 / 引流诱导 / 违禁品 / 侵权，参考法规原文并标注来源）+ 各平台专属规则（参考各平台公开社区规范）
  4. **检索（RAG）**：接入免费 bge-m3 → 内存向量索引 → 按目标平台过滤后召回 Top-K
  5. **提示词工程**：规则库放提示词前缀吃缓存（成本降至 1/50）；约束 JSON 输出
  6. **判定输出**：四级分级 + 判定理由 + 处置建议 + 违规片段定位 + 修改建议
  7. 两处调用：**平台审核**（本平台）+ **按目标平台预检**
- **产出物**：审核与预检能力 + 规则库 + 《提示词与检索设计说明》（含缓存命中率实测）。
- **验收标准**：六类维度各准备样本能正确判定；同一内容在不同目标平台下能给出不同结论；理由与建议具体可用（不是「请注意合规」这类空话）。

---

## 阶段 6：跨平台内容适配（第二创新点）

- **入口**：阶段 5。
- **做什么**：
  1. **各平台格式约束落地**：标题/正文字数上限、话题标签规则、结构要求（以各平台公开创作规范为准）
  2. **适配提示词设计**：按平台生成对应形态 —— 小红书（短标题 + 口语化 + 话题标签）、微博（≤140 字 + 话题）、公众号（长文 + 段落结构）、B站（标题 + 简介 + 标签）、抖音（口播脚本 + 分段）
  3. **格式约束自检器**（可自动校验）：字数、标签数量、结构完整性 → 超限自动提示或截断
  4. **适配后合规预检**：复用阶段 5 的规则引擎，按目标平台检查并给修改建议
  5. 适配结果的**导出与复制**（Markdown / 纯文本 / 剪贴板）
  6. 适配记录留存（版本、目标平台、时间）
- **产出物**：跨平台适配功能 + 《适配规则与提示词设计说明》。
- **验收标准**：一篇内容能生成多平台版本且**格式自检全部通过或给出明确警告**；适配后合规预检能发现平台专属问题（如站外引流）；导出产物可直接粘贴使用。

## 阶段 7：人机协同闭环

- **入口**：阶段 6。
- **做什么**：审核工作台（待审队列、结论与理由展示、通过/改判/驳回，**改判原因必填**）；创作者端反馈展示（违规片段高亮 + 修改建议 + 重新提交）；改判记录留存与统计。
- **产出物**：完整闭环 + 《人机协同设计说明》。
- **验收标准**：完整走通「投稿 → 预检 → 提交 → 初判 → 审核员改判 → 创作者看反馈修改 → 重提」。

---

## 阶段 8：评测集与实验（论文实验章节）

- **入口**：阶段 7。
- **做什么**：
  1. **审核评测集**：核验并抽样公开数据集（ToxiCN / COLD，注意 HuggingFace 走镜像）+ 自建六类样本 + 改判记录
  2. **审核实验**：三方案对比（关键词规则 / 纯大模型 / RAG+大模型）→ 准确率 / 召回率 / F1 / 成本 / 耗时；消融实验（不同模型规模）
  3. **适配评估**（新增）：格式约束满足率（自动校验）+ 人工评分（风格符合度 / 信息保留度 / 可读性）+ LLM 评判与人工评分一致性
  4. 结果分析文档（含局限说明：合成样本、循环论证风险的规避方式）
  5. 系统内「评测中心」页面：可一键跑、可看结果表
- **产出物**：《评测集构建说明》+ 实验数据表 + 分析结论。
- **验收标准**：能一键跑出实验表格，结果可复现。
- **注意**：公开数据集含真实粗俗内容，**只用于跑指标，绝不进入演示流程**。

- **验收标准**：在你自己电脑上从零启动一次成功；你能独立讲完一遍完整演示。
