# 系统功能说明

> 用途：说清这个系统「是什么、给谁用、怎么用、做出来能拿出什么结果」。
> 这份文档是《开题报告》的「主要研究内容」、论文「需求分析」章节、以及答辩讲解的基础材料。

## 一、这个系统是什么

**一句话**：它是**面向多平台的内容创作、适配与合规管理平台** —— 创作者在这里创作和管理内容，系统按目标平台（公众号 / 小红书 / 微博 / B站 / 抖音）自动**适配内容形态**并做**合规检查**；平台运营人员在这里审核内容、管理用户与规则。

**先说清一条硬边界（很重要，答辩必会被问）**：本系统**不对接任何真实第三方平台的发布接口**，不会把内容真正发到公众号、小红书上去。原因是个人开发者做不到，已完成调研见 [decisions-multiplatform.md](decisions-multiplatform.md)：

- 微信：发布接口对**个人主体账号已被官方回收**（官方文档：2025 年 7 月起）；
- 抖音：发布权限**不接受个人开发者申请**，需企业资质；
- 小红书：无公开接口，自动化封号风险最高；
- 微博 / 知乎：官方接口只面向企业认证用户。

所以系统内**保留「目标平台」这一概念**（每个平台带自己的规则集和格式要求），把价值落在**内容适配**和**合规预检**上 —— 这两件事不依赖任何平台接口，但对创作者有实打实的用处。

**它管三件事**：管人（用户 / 角色 / 权限）、管内容（创作 → 适配 → 审核 → 发布 → 反馈全流程）、管风险（按平台规则的合规审核 + 举报处理）。

## 二、系统里的三种人（登录后各自看到什么）

### 1. 超级管理员 —— 管人和管全局
菜单：`数据看板` `用户管理` `角色管理` `菜单管理` `稿件管理` `分类标签` **`平台管理`** `审核规则库` `敏感词库` `举报处理` `审核记录` `评测中心`
日常动作：审用户、分权限、维护平台清单与规则库、看平台数据、跑评测实验。

### 2. 审核员 —— 核心岗位（人机协同里的人）
菜单：`数据看板` `审核工作台` `稿件查询` `举报处理` `审核记录`
日常动作：看待审队列 → 看智能体的风险等级、理由、违规片段、处置建议 → **采纳 / 改判 / 驳回 / 通过**（改判必须填原因）。始终握有最终决定权。

### 3. 创作者 —— 内容的来源
菜单：`我的稿件` `投稿` **`跨平台适配`** `我的反馈`
日常动作：写稿 → 发布前检查 → 提交 → 收到驳回反馈后修改重提；**把内容适配成各平台版本并导出**。

## 三、内容的一生（两条线）

```
【本平台主线：内容能否在本平台发布】
草稿
 └─(发布前检查)→ 智能体预检：风险提示 + 修改建议（不阻断，可反复查）
     └─(提交发布申请)→ 待审核
         └─ 智能体分级初判 → 审核员终审（人机协同）
             ├─→ 已发布 ──(被举报且复核成立)──→ 已下架
             ├─→ 已驳回（附违规片段 + 修改建议）→ 创作者修改后重提
             └─→ 已阻断（严重违规，同时标记作者）

【多平台适配支线：内容怎么发到别的平台】（推荐审核通过后做）
选目标平台（可多选）
   → 智能体按各平台生成适配版本
   → 格式约束自检（字数 / 话题标签 / 结构，可自动校验）
   → 按该平台规则做合规预检（给出修改建议）
   → 导出 / 复制到剪贴板（本系统不做真实发布）
```

关键分工：**智能体只给建议和产物，不单独决定任何稿件的最终状态。**

## 四、五个具体场景（点几下 → 看到什么）

### 场景 1：创作者投稿，发布前就被拦下（本平台主线）

点「发布前检查」后：

```
┌──────────────────────────────────────────────┐
│ 发布前检查结果                                 │
│  风险等级：◐ 疑似                              │
│  命中规则：AD-003 绝对化用语（《广告法》第九条） │
│            FB-011 功效承诺                     │
│  风险片段：「全网最低价」「三天见效」            │
│  修改建议：「全网最低价」→ 改为"限时优惠"或删除；│
│            「三天见效」→ 删除功效承诺或补充依据   │
│  说明：本次仅提示不阻断；提交后仍会进入正式审核   │
└──────────────────────────────────────────────┘
```

按建议改掉 → 再查 → 显示「未发现明显风险」→ 提交发布申请。

### 场景 2：跨平台适配（**新增，最亮的演示点**）

创作者点「跨平台适配」→ 勾选目标平台 → 系统按平台分别生成版本 + 自检：

```
┌──────────────────────────────────────────────────────────────┐
│ 跨平台适配   稿件 #1030《家庭收纳的 5 个小技巧》               │
│ 目标平台：☑小红书  ☑微博  ☑B站  ☐公众号  ☐抖音                 │
│                                              [开始适配]       │
├──────────────────────────────────────────────────────────────┤
│ ▼ 小红书版                                    ✅ 格式自检通过  │
│   标题：收纳做对了，家里大一倍 ✨                              │
│   正文：姐妹们！我家 60 平也能装下所有东西 🙌                  │
│         最近整理了 5 个超好用的收纳技巧……（口语化 + emoji）    │
│   话题：#收纳 #小户型 #家居好物                                │
│   平台合规：◐ 疑似 —— 命中「小红书·站外引流」（正文含          │
│   "加我微信领清单"），建议删除该句                             │
│                                            [复制] [导出]      │
│ ▼ 微博版    ✅ 格式自检通过（128 字，含话题 #收纳技巧#）        │
│ ▼ B站版     ⚠ 格式警告：标题 82 字超出限制（≤80），已自动截断   │
└──────────────────────────────────────────────────────────────┘
```

**这个场景的价值**：同一篇内容，各平台的形态要求完全不同（小红书要口语化 + 话题标签，微博要 140 字内，抖音要口播脚本）。人工逐个改写很费时，这正是大模型擅长的活；而"字数 / 标签 / 结构"的格式约束是**可以自动校验**的，所以适配效果能被量化评估（见评测阶段）。

### 场景 3：审核员的正式审核（人机协同）

```
┌─────────────────────────────────────────────────────────────┐
│ 审核工作台                        [待审 12] [我已处理 38]    │
├──────────────────────┬──────────────────────────────────────┤
│ 待审队列              │ 稿件：#1024 《三天见效的美肤面膜》     │
│ ──────────────────   │ 作者：美妆小铺   提交：10-16 14:20     │
│ #1024 三天见效     ● │ ─────────────────────────────────── │
│ #1023 限时秒杀     ● │ 智能体判定                            │
│ #1022 旅行日记     ◐ │  风险等级：■ 违规                     │
│ #1021 育儿心得     ○ │  判定理由：正文第三段承诺「三天见效」， │
│                      │   构成功效承诺；并含「国家级」绝对化    │
│                      │   用语，涉嫌违反广告法第九条            │
│                      │  违规片段：「国家级配方」「三天见效」   │
│                      │  命中规则：AD-003、FB-011              │
│                      │  处置建议：驳回并要求修改              │
│                      │ ─────────────────────────────────── │
│                      │ [采纳建议]  [改判]  [通过]  [驳回]     │
└──────────────────────┴──────────────────────────────────────┘
```

审核员点「采纳建议」→ 稿件变「已驳回」并带上违规片段与建议；若认为判定不对 → 点「改判」（**必填改判原因**）→ 稿件通过。这条差异会被记录，**进入评测数据集**（人机协同的副产品，也是最真实的标注数据）。

### 场景 4：创作者收到反馈并重提

「我的稿件」看到「已驳回」+ 理由 → 点开看到**高亮的违规片段 + 修改建议** → 就地修改 → 重新提交。

### 场景 5：举报处理

创作者 A 举报 B 的已发布稿件 → 审核员在「举报处理」看到 → 触发复审（智能体重跑）→ 成立则下架，不成立则驳回举报。

## 五、智能体到底"智能"在哪

系统里的智能体有三项能力，**都不碰平台接口，零风控风险**：

| 能力 | 输入 → 输出 | 为什么有价值 |
|---|---|---|
| **跨平台内容适配** | 一篇内容 + 目标平台集合 → 各平台适配版本 + 格式自检 + 平台合规提示 | 人工逐个平台改写极其费时；各平台形态要求差异大 |
| **按平台规则的合规预检** | 内容 + 目标平台 → 该平台规则下的风险等级 + 命中规则 + 修改建议 | 同一内容发不同平台，规则不同（小红书严管站外引流、微博/公众号各有侧重） |
| **平台审核（本平台）** | 稿件 → 四级风险 + 判定理由 + 违规片段 + 处置建议 | 运营方的审核义务；替代低效的全人工通读 |

和普通管理系统的对比（**答辩最容易被追问的点**）：

| 维度 | 普通管理系统 | 本系统 |
|---|---|---|
| 识别方式 | 敏感词匹配：命中「最」字就报 | **语义理解 + 规则检索**，能看语境 |
| 典型例子 | 「最好的我们」（电影名）和「全网最好」（广告）**一起误报** | 前者放行，后者判违规并给出依据 |
| 判定输出 | 是 / 否 + 命中的词 | **四级风险 + 理由 + 违规片段 + 修改建议** |
| 多平台 | 不涉及 | **按目标平台分别适配与判定** |
| 规则可追溯 | 无 | 每条判定标注规则编号与法规 / 规范来源 |
| 效果可度量 | 无法评估 | 有评测集，有准确率 / 召回率 / F1 与适配质量评分 |
| 成本 | 纯人时 | 约 0.4 分钱/次 + 少量人时 |

推荐在答辩时直接用「最好的我们」这个例子说明创新点。

## 六、系统边界（主动划清，避免被问倒）

- **不做任何真实第三方平台发布对接**（不调接口、不做浏览器自动化）—— 原因见第一节，系统内所有多平台能力均为**模拟实现**，论文与答辩必须写清讲清
- 不做面向普通网友的浏览端（无推荐流、点赞、关注、私信）
- 不做评论模块
- 本期只做**文本**内容的适配与审核；图片 / 视频列为后续扩展
- 不接真实平台数据（不爬取），稿件来自系统内投稿 + 种子数据脚本
- **智能体不自动处置**：不能自己删稿、封号，处置一律经审核员

## 七、数据从哪来

1. **平台清单与格式约束**：按各平台公开的创作规范整理（平台名称真实、规则来源真实，但不对接接口）
2. **规则库**：通用六类规则（广告法极限词 / 虚假宣传 / 低俗擦边 / 引流诱导 / 违禁品 / 侵权）+ 各平台专属规则，每条标注来源
3. **种子数据脚本**：测试用户（三种角色）、数百篇稿件、分类标签、平台清单 —— 让系统一启动就有内容可看
4. **六类违规样本**：专门准备「文明但明显违规」的样本，用于演示（答辩场合安全）
5. **公开数据集**（ToxiCN / COLD）：用于跑审核指标，**不入演示流程**（内容粗俗）
6. **改判记录**：系统运行中积累的真实标注数据

## 八、做出来之后能拿出哪些具体结果

| 结果 | 具体形态 |
|---|---|
| 一个能跑的系统 | 三端一键启动：Vue 前端 + Spring Boot 后端 + Python 智能体服务 + MySQL |
| 三种角色可登录演示 | 管理员 / 审核员 / 创作者，菜单与权限各不相同 |
| 一条完整的演示流程 | 5 分钟走完：投稿 → 预检 → 提交 → 智能体分级 → 审核员改判 → 创作者修改重提 |
| **跨平台适配演示** | 一篇内容 → 小红书 / 微博 / B站 三版适配 + 格式自检 + 平台合规提示 + 导出 |
| 一个真正干活的智能体 | 三项能力：平台审核、按平台规则预检、跨平台内容适配 |
| 一个可追溯的规则库 | 通用六类 + 平台专属规则，每条标注法规或规范来源 |
| **一张可复现的实验数据表** | 审核：关键词规则 / 纯大模型 / RAG+大模型 三方案对比（准确率、召回率、F1、成本、耗时）；**适配：格式约束满足率 + 人工评分 + LLM 评判一致性**。系统内有「评测中心」页面可直接跑 |
| 一个数据看板 | 用户数、稿件数、待审数、投稿趋势、审核结果分布、**人工改判率**、**各平台适配次数** |
| 一套文档 | 技术说明文档、项目说明文档、每阶段开发笔记、答辩问答准备 |
| 论文素材 | 需求分析、系统设计、系统实现、测试、实验 —— 全部来自上述产出；多平台可行性调研可直接用于「可行性分析」章节 |
