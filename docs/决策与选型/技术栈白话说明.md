# 技术栈白话说明

> 用途：让你（和答辩时的你）能用**几句话**说清每一样技术为什么在这里、它干了什么活。
> 每个条目四行：**是什么 → 在你系统里干什么 → 为什么选它 → 答辩怎么说**。
> 这份文档可以直接并进《技术说明文档》或论文的「技术选型」章节。

## 一、整体结构：谁调用谁

```
┌────────────────────────────────────────────────┐
│ 浏览器（你自己电脑上打开的那个页面）              │
│ Vue 3 + Element Plus + Pinia + Vue Router       │
│ Axios 负责向后端发请求                           │
└───────────────┬────────────────────────────────┘
                │ HTTP（JSON 数据）
┌───────────────▼────────────────────────────────┐
│ 后端主系统  Spring Boot 4.1.1（Java）            │
│ ├─ Sa-Token      ：登录与权限（门禁系统）        │
│ ├─ MyBatis-Plus  ：读写数据库（翻译 + 搬运）     │
│ └─ 业务模块      ：用户/角色/菜单/稿件/举报/敏感词 │
└──────┬─────────────────────────┬───────────────┘
       │ JDBC                    │ HTTP（JSON）
┌──────▼────────┐    ┌───────────▼─────────────────┐
│ MySQL 8.0.46  │    │ 智能体服务 FastAPI（Python）  │
│ 全部业务数据   │    │ ├─ 审核判定流水线（自研）     │
└───────────────┘    │ ├─ 步骤：检索/定位/判定/校验  │
                     │ └─ 检索：内存向量索引（可选） │
                     └───────────┬─────────────────┘
                                 │ HTTPS
                     ┌───────────▼─────────────────┐
                     │ DeepSeek（判定与写理由）      │
                     │ 硅基流动 bge-m3（算向量）     │
                     └─────────────────────────────┘
```

**一句话概括架构**：主系统管「数据与权限」，智能体服务管「判定」，两者用 HTTP 接口解耦。这样智能体服务挂了，主系统照样能跑（退回人工审核）—— 答辩演示时更稳。

## 二、前端（用户能看到的部分）

### 1. Vue 3
- **是什么**：前端框架，负责把页面「拼」出来。
- **干什么**：所有你看到的界面（登录页、菜单、表格、表单）都由它渲染；数据一变，页面自动跟着变。
- **为什么选它**：学校要求用 Vue；Vue 3 是当前主版本，中文资料最多。
- **答辩怎么说**：「前端用 Vue 3 实现前后端分离，页面通过接口取数据，不依赖后端模板渲染。」

### 2. Vite
- **是什么**：前端的开发与打包工具。
- **干什么**：启动前端开发服务器；把代码打包成浏览器能运行的文件；改代码后页面自动刷新（热更新）。
- **为什么选它**：Vue 官方推荐的默认工具（`create-vue` 生成的项目自带）。
- **答辩怎么说**：「用 Vite 作为构建工具，开发时提供热更新，打包时产出静态资源。」

### 3. Element Plus
- **是什么**：Vue 3 的 UI 组件库（成品控件箱）。
- **干什么**：表格、分页、表单、弹窗、树形菜单、上传这些控件直接拿来用，不自己写。
- **为什么选它**：国内最主流的 Vue 3 组件库，文档中文、示例全，能省掉大量界面代码。
- **答辩怎么说**：「界面基于 Element Plus 组件库实现，保证交互一致性，把精力集中在业务逻辑上。」

### 4. Pinia
- **是什么**：前端状态管理，可以理解为前端的「公共储物柜」。
- **干什么**：存放跨页面共享的数据 —— 主要是登录用户信息、权限、菜单、Token。
- **为什么选它**：Vue 官方推荐，比老一代 Vuex 更简单。
- **答辩怎么说**：「用 Pinia 管理登录态和权限信息，避免每个页面重复请求用户数据。」

### 5. Vue Router
- **是什么**：前端路由，相当于系统里的「门牌系统」。
- **干什么**：决定点哪个菜单显示哪个页面；配合路由守卫实现「没登录就踢回登录页」「没权限就进不去」。
- **为什么选它**：Vue 官方路由方案。
- **答辩怎么说**：「路由守卫负责前端的第一层权限拦截，真正的权限校验仍在后端。」

### 6. Axios
- **是什么**：HTTP 请求库，前端的「快递收发员」。
- **干什么**：所有前端→后端的请求都通过它发出；统一加 Token、统一处理错误提示。
- **为什么选它**：最主流的请求库，拦截器机制便于统一处理登录失效。
- **答辩怎么说**：「Axios 拦截器统一注入登录凭证并处理 401，避免每个请求重复写逻辑。」

## 三、后端主系统（Java）

### 7. Spring Boot 4.1.1
- **是什么**：Java 后端框架，整个系统的「中枢」。
- **干什么**：启动后端服务、对外提供 HTTP 接口、把数据库操作与业务逻辑组织起来。所有后端接口都跑在它上面。
- **为什么选它**：学校指定；它把繁琐的配置自动化了（自动配置、内嵌服务器），比裸 Java 开发容易得多。
- **答辩怎么说**：「后端采用 Spring Boot 构建 RESTful 接口，通过分层（Controller-Service-Mapper）组织业务逻辑。」

### 8. JDK 17
- **是什么**：Java 运行环境。
- **干什么**：编译和运行 Java 代码。Spring Boot 4.1.1 最低要求就是 Java 17。
- **为什么选它**：本机已装，且满足要求，无需升级。

### 9. Maven
- **是什么**：Java 的依赖管理与构建工具，后端的「采购 + 打包流水线」。
- **干什么**：在 `pom.xml` 里声明需要哪些库，它自动下载；一条命令把项目打成可运行的 jar 包。
- **为什么选它**：Java 生态标准工具，本机已装 3.9.16。
- **答辩怎么说**：「用 Maven 做依赖管理，配置阿里云镜像加速国内下载。」（**注意**：答辩机若断网需提前打好包，本项目已确认联网。）

### 10. MyBatis-Plus
- **是什么**：数据持久层框架（ORM 的一种），Java 与 MySQL 之间的「翻译 + 搬运工」。
- **干什么**：把 Java 对象和数据库表对应起来。单表增删改查不用写 SQL（`save()`/`list()`/`getById()`），复杂查询写 SQL。
- **为什么选它**：比 JPA 更贴近 SQL、单表 CRUD 代码量最小、中文资料最全。答辩时你能准确说出「它替我生成了 SQL」。
- **答辩怎么说**：「持久层用 MyBatis-Plus，单表操作由框架生成 SQL，复杂查询手写 SQL 以保证可控性。」

### 11. Sa-Token
- **是什么**：轻量级 Java 认证授权框架，系统的「门禁系统」。
- **干什么**：登录（发令牌）、会话管理、权限校验（谁能访问哪个接口、看到哪个按钮）。三件事：**你是谁、你登录了吗、你能不能干这个**。
- **为什么选它**：登录一行 `StpUtil.login(id)`，鉴权一个注解 `@SaCheckPermission`，答辩一句话能讲完；Spring Security 要讲过滤器链，讲不清就是扣分点。（Sa-Token 在 Gitee 上有 4.8 万+ star，中文文档完整。）
- **答辩怎么说**：「认证授权用 Sa-Token 实现，登录后签发 Token；接口用注解做权限校验，前端路由守卫配合后端共同拦截非法访问。」

### 12. MySQL 8.0.46
- **是什么**：关系型数据库。
- **干什么**：存全部业务数据 —— 用户、角色、菜单、稿件、审核记录、规则库、举报、敏感词。
- **为什么选它**：你学过、本机已装、毕设最常用。

## 四、智能体服务（Python，创新点所在）

### 13. Python 3.11 + FastAPI
- **是什么**：Python 语言 + 它的 Web 框架。FastAPI 是智能体服务的「接线盒」。
- **干什么**：把 Agent 能力包装成一个 HTTP 服务，让 Java 主系统能调用它（`POST /audit`）。
- **为什么选它**：你有 Python 基础；FastAPI 写起来最简洁、自带接口文档（`/docs` 页面能直接测试接口，演示时很好用）。
- **答辩怎么说**：「智能体作为独立的 Python 服务部署，通过 HTTP 接口与主系统集成，便于独立迭代与替换。」

### 14. openai 官方 SDK
- **是什么**：调用大模型的统一客户端库。
- **干什么**：用它去调 DeepSeek（DeepSeek 提供 OpenAI 兼容接口）。换模型只改一个配置项。
- **为什么选它**：一套写法通吃多家模型，正好满足「主用 DeepSeek、可降级到免费额度」的需求，也是论文里做「不同模型对比实验」的前提。
- **答辩怎么说**：「通过 OpenAI 兼容接口调用大模型，模型可配置可替换，并据此完成了不同模型的对比实验。」

### 15. DeepSeek API
- **是什么**：大模型服务（云端的「大脑」）。
- **干什么**：真正做「读懂稿件 → 判断是否违规 → 写出判定理由和修改建议」这件事。
- **为什么选它**：中文强、价格极低（flash 模型约 0.4 分钱/篇）、支持工具调用（Tool Calls）和 JSON 输出。

### 16. 硅基流动 bge-m3（向量化模型）
- **是什么**：embedding 模型，把文字变成一串数字（向量）。
- **干什么**：把「审核规则」和「稿件内容」都变成向量，然后找出**语义最接近的规则** —— 这就是 RAG（检索增强生成）里的「检索」。
- **为什么选它**：免费（￥0/百万 tokens）、国内直连、不用在本机跑模型（本机 4G 显存跑不动）。
- **答辩怎么说**：「规则检索采用 bge-m3 向量模型 + 余弦相似度召回，无需向量数据库。」

### 17. 审核判定流水线（自研）
- **是什么**：整个创新点的核心代码，把「规则准备 → 关键词定位（可选）→ 拼提示词 → 调模型 → 解析并校验 JSON → 输出结构化结论」串成一条固定流程（`agent/judge.py`）。题目里的「单智能体」指系统只有一个承担智能判定的服务，不是指模型会自主规划。
- **干什么**：每次审核/预检都按这条流程走。步骤由代码固定，模型只在「判定」这一步做决策；每一步都有明确的失败处理——检索失败回退全量规则、模型失败返回 503、JSON 非法返回 422、编造的规则编号被过滤。
- **为什么自研**：流程短、边界清楚，自研能让每一步都可见可控；不引入 LangGraph/LangChain 是为了避免"框架替我做完了，我却说不清"。**需要说明的是：它不是让模型自主选工具的 Agent 循环**；各步骤已拆成独立函数，后续若要加工具调用（如让模型决定是否再检索、是否细看某一段），是在流程前加一层调度，而不是重写。
- **答辩怎么说**：「审核是一条确定性流水线：代码决定步骤，模型负责判定；每一步的输入输出、失败降级都可追踪。当前任务边界固定，不需要模型自主规划；需要时可在流水线前加一层工具调度。」

### 18. 内存向量检索（自研，无向量数据库）
- **是什么**：不装向量数据库的检索方式。
- **干什么**：规则库只有几百条，直接在内存里算余弦相似度，毫秒级返回。
- **为什么这么设计**：多一个数据库就多一层运维与解释成本；几百条数据用不上专业向量库。**规模变大时再换 Chroma/FAISS，只需替换 `rag.retrieve` 的实现，入参出参不变。**
- **答辩怎么说**：「考虑到规则库规模较小，采用内存向量索引，避免引入额外中间件；检索逻辑集中在 `rag.retrieve`，规模增长后可平滑替换为专业向量库。」

## 五、辅助

### 19. 一键启动脚本（.bat）
- **是什么**：Windows 批处理脚本。
- **干什么**：双击一下，按顺序启动后端、前端、智能体服务，省得每次手动开三个窗口。
- **为什么需要**：你没有服务器也没有 Docker，答辩当天少一个手动步骤就少一处出错可能。

### 20. Git（本地版本控制）
- **是什么**：代码版本管理工具。
- **干什么**：每个阶段结束时留一个还原点，改坏了能回退。
- **说明**：**由我操作，你不需要学**。你只要知道"每个阶段结束都有一个可回退的存档"即可。

## 六、一次「审核」请求的完整链路（答辩必讲）

以审核员点下「提交智能审核」为例：

1. **浏览器**：审核员点击按钮 → Axios 发出 `POST /api/article/{稿件ID}/agent-audit`，请求头带登录 Token。
2. **门禁**：Sa-Token 校验 Token 是否有效、该用户是否有「审核」权限 → 不通过直接返回 401/403。
3. **取数据**：后端用 MyBatis-Plus 从 MySQL 取出这篇稿件的正文、作者、历史记录。
4. **转发**：后端通过 HTTP 把稿件内容 + 规则库版本号发给 Python 智能体服务（契约见《Agent 接口契约》）。
5. **准备规则**：主系统从数据库取出启用的规则（通用 + 本平台专属）与敏感词，随请求下发。正式审核默认走 E1「最小规则目录」：提示词里只放规则的编号/名称/类别/建议等级，不放规则正文，规则依据由主系统按编号回查数据库；适配后的合规预检仍启用 RAG，用 bge-m3 在内存里召回 Top-K 条最相关的规则。
6. **判定**：把「规则目录（或检索出的规则）+ 稿件正文 + 平台约束」组装成提示词发给 DeepSeek，要求只输出 JSON；返回后校验等级范围与规则编号白名单。
7. **结构化输出**：DeepSeek 返回 JSON —— 风险等级（通过/疑似/违规/严重）、判定理由、违规片段、修改建议。
8. **落库**：后端把结论写入「审核记录」表（`audit_record`），稿件保持「待审核」；审核员终审后才改变稿件状态。
9. **回显**：工作台展示结论与理由；审核员可**改判**（改判原因必填，记录留存作为标注数据）。
10. **反馈**：若判为违规，创作者在投稿页看到高亮的违规片段 + 修改建议，可修改后重新提交。

**这条链路能讲完，答辩的「系统实现」部分就稳了。**

## 七、可能的追问与答法

**Q：为什么用两个语言（Java + Python）？不能都用 Java 吗？**
A：主系统用 Java 是课程与导师要求；智能体用 Python 是因为大模型的工具生态、向量检索、评测库集中在 Python，迭代更快。两者通过 HTTP 契约解耦，Agent 出问题不影响主系统，也可独立替换实现。

**Q：为什么不用 Spring AI / LangChain 这类现成框架？**
A：判定流水线自己实现，是为了掌控每一步（检索、定位、提示词、解析、校验），也便于写论文时说明设计细节。这里没有让模型自主选工具，所以不需要 LangChain/LangGraph 的编排能力；各步骤已拆成独立函数，后续若要接入框架是"加一层"而不是重写。

**Q：为什么不用向量数据库？**
A：规则库规模只有数百条，内存余弦相似度足够且毫秒级返回；不引入中间件可以减少运维与部署复杂度。检索逻辑集中在 `rag.retrieve`，规模增长后可平滑换用专业向量库。

**Q：大模型会不会自己决定把稿件删掉？**
A：不会。智能体只输出「建议 + 理由」，最终处置由审核员决定并可改判；系统设计上智能体没有直接执行处置的权限。这一点既是业务要求（平台审核责任），也是安全设计（人在回路）。

**Q：模型调用花钱吗？**
A：主用 DeepSeek `deepseek-flash`，实测约 0.4 分钱/篇；embedding 走硅基流动免费额度。全项目月成本控制在 50 元以内。

**Q：如果模型服务不可用怎么办？**
A：后端调用带超时与重试，失败时优雅降级到「人工审核」路径（退回敏感词库 + 人工判定），主系统功能不受影响。开发期另有响应回放模式用于离线测试。
