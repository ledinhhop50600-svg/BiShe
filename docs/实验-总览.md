# 实验总览（阶段 5～8）

> 用途：把散落在各报告里的实验结论汇总到一页，方便写论文与答辩时快速定位。
> 详细数据见各报告；本页只给结论与文件索引。

## 一、审核实验（428 条扩展集，2026-10-29）

评测集：核心自建 28 条（分层设计）+ ToxiCN 200 条（正负各 100）+ COLD 200 条（冒犯/非冒犯各 100）；
二分类口径为 `riskLevel >= 2` 阻断。公开集只做二分类与外部效度，核心集才看规则/分级。

### 总体（1 轮；准确率受公开集占比影响，必须同时看召回与误报）

| 方案 | 准确率 | 违规召回 | 误报 | 核心准确率/召回 | 公开准确率/召回 | 规则召回 | 平均 token |
|---|---|---|---|---|---|---|---|
| A 关键词规则 | 50.5% | 3.8% | 8 | 64.3% / 58.3% | 49.5% / 0.5% | 0% | 0 |
| B 纯大模型 | 67.8% | 41.5% | 14 | 92.9% / 83.3% | 66.0% / 39.0% | 0% | 948 |
| C RAG+大模型（原版） | 73.4% | 59.9% | 29 | 85.7% / 83.3% | 72.5% / 58.5% | 59.4% | 1466 |
| C1 RAG+紧凑检索 | 72.4% | 53.8% | 20 | 96.4% / 91.7% | 70.8% / 51.5% | 62.5% | 1177 |
| E2 B+后置归因 | 67.5% | 41.0% | 14 | 96.4% / 91.7% | 65.5% / 38.0% | 45.8% | 952 |
| E1 B+最小规则目录 | **74.1%** | 58.0% | 22 | **96.4% / 91.7%** | 72.5% / 56.0% | **83.3%** | 1263 |
| D 全量规则+大模型 | **74.1%** | **60.8%** | 28 | 85.7% / 83.3% | **73.2% / 59.5%** | 79.2% | 2061 |

### 解读

1. **E1 是新的生产默认**：E1（B + 最小规则目录）与 D 并列总体准确率 74.1%，token 只有 D 的 61%；
   核心集 96.4% / 91.7%，规则引用召回 83.3%，比原版 C 更准、更可追溯、更便宜。
   规则只给编号/名称/类别/等级，引用编号仍回库校验，人工终审保留。
2. **C1 是 C 的成本优化版**：token 1466 → 1177（-20%），规则召回 59.4% → 62.5%，核心准确率 85.7% → 96.4%；
   公开集召回 58.5% → 51.5%。适合核心业务/成本敏感路径，不是全面替代。
3. **E2 判定强、引用弱**：核心准确率/召回 96.4% / 91.7%，token 952，但规则召回只有 45.8%；
   关键词/字符重合的后置归因不够，保留为“判定与归因分离”的研究方向。
4. **D 是可追溯性上限**：规则召回 79.2%、违规召回 60.8%，但 token 是 C 的 1.41 倍；只作全量规则消融。
5. **关键词基线在公开集几乎失效**：公开集召回 0.5%，再次说明“没命中关键词就放行”不可行。

### 历史口径（52 条核心集，保留用于对照）

- v3 严格口径（2 轮）：C 85% > D 83% > B 78%；
- v4 放宽口径（1 轮，2026-10-19）：B 83% > C/D 81%；
- v4 复测（1 轮，2026-10-29）：B 81% > D 79% > C 75%。
- 这些是 52 条核心集上的结果，不能和 428 条扩展集的总体准确率直接横比。

### 其他实验

- **模型对比**：deepseek-v4-pro 反而更差（B 65 / C 73 / D 79 vs flash 78 / 85 / 83）；
  不能假设更贵更强一定更好。
- **关键词定位消融**：3 条长文上准确率相同，E 省 7% token；篇幅更长时收益才明显。
- **长文本故障**：DeepSeek 默认思考模式会耗尽输出预算导致空内容；关闭后成本降 55%、耗时降 60%，
  准确率不变。
- **标注一致性**：15 条争议样本盲评，四级 Cohen's κ = 0.51；裁决后 5 条标签变更。

### 速度与内存优化（2026-10-29）

- **适配并行**：三平台短文 12.7 s → 6.1 s，长文 21.8 s → 9.6 s，格式与形态不变；
  合并一次调用反而更慢（短文 9.4 s、形态 2/3），通用提示词只快约 0.4 s 但形态 2/3。
- **思考强度**：none 5.6 s / 608 token；low 8.5 s / 1136；high 8.6 s / 1116。判定等级均为 2，
  没有明确质量收益，默认继续 `none`。
- **内存**：前端 dev → preview 222.4 → 98.1 MB；后端小堆 209.2 → 172.9 MB，
  且 `mvn spring-boot:run` 另有 256.5 MB 的 Maven 父进程，打包 jar 后约 204 MB；
  MySQL Private 664.4 MB（performance_schema 230.9 MB）需全局配置才能降；Agent 75.1 MB。
- 详见 `docs/实验-速度优化.md` 与 `docs/性能优化实验.md`。

## 二、适配质量评估（4 篇 × 3 平台）

| 指标 | 结果 |
|---|---|
| 格式自检通过率 | 12/12（100%，`paper-20261019-v2`）；另一批 11/12（小红书长文 1111/1000 超限） |
| 单次适配耗时 | 约 6 秒（改写 + 合规预检） |
| 长文 #16 压缩比 | 小红书 0.38 / 公众号 0.94 / 抖音 0.42 |
| LLM 风格/保留/可读（1-5） | 4.00 / 4.58 / 4.67（区分度低） |
| 人工评分 | 待填（`docs/eval/adaptation-human-sheet.csv`） |

**结论**：格式约束可由程序稳定校验；长文压缩是弱项（出现过超限），必须保留"警告而不是静默通过"；
LLM 评分偏宽松，需人工评分对照。

## 三、人机协同指标（系统可观测）

- 智能体判定分布（0/1/2/3 + 失败）；
- 采纳率、改判率、人工判定占比；
- 每条判定的 token、耗时、模型；
- 改判原因原文。

改判率口径：改判 /（采纳 + 改判）；疑似转人工不算改判；人工判定不计入分母。

## 五、局限（论文必须写）

1. 审核评测集扩到 428 条，但核心业务样本仍只有 28 条，且由作者单独标注；公开集只能补二分类统计量，不能补广告法/引流/违禁品的业务覆盖；
2. 公开集 ToxiCN/COLD 是短评论，与本平台图文分布不同；
3. 适配评估只有 4 篇稿件、3 个平台，LLM 评分区分度低，人工评分未完成；
4. 平台字数等约束会随平台改版变化，系统内数据需人工维护；
5. 实验脚本依赖本地 Agent 与后端，复现需按 `start.bat` 启动完整环境。
