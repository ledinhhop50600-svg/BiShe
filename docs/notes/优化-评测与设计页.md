# 优化记录：评测中心可视化、需求设计与架构设计页

> 日期：2026-10-29
> 目标：把"实验结果、系统设计、功能细节"从表格和文档搬进网页，答辩时可以直接指着讲

## 一、评测中心改版

页面：`frontend/src/views/eval/index.vue`

数据流：

```
tools/experiment_compare.py  → docs/eval/audit-results.json
tools/eval_adaptation.py     → docs/eval/adaptation-results.json
tools/experiment_speed.py    → docs/perf/speed-experiment.json
tools/perf_report.py         → docs/perf/perf-latest.json
docs/perf/optimization-summary.json（人工整理的内存前后对照）
        ↓
GET /api/eval/results（EvalController 读取，不在 Java 重算）
        ↓
ECharts：柱状图 / 折线图 / 散点图 / 雷达图 / 环图
```

页面按五个 tab 组织：

1. **总览**：方案指标柱状图（第一轮四方案，扩展集六方案）、质量-成本散点、评测集构成、适配策略耗时、内存前后对照；
2. **审核对比**：分层准确率曲线、规则召回、严格 v3 / 放宽 v4 对照、结论卡片；
3. **适配质量**：平台形态雷达、长文压缩比、人工 vs LLM、格式未通过、演示批次；
4. **性能优化**：前端/后端/MySQL/Agent 四类卡片，并行耗时、思考强度、内存构成、代价与边界；
5. **数据明细**：原始表格和复现命令，默认不打扰阅读。

`EvalController` 新增 `performance`、`speed`、`optimization` 三个字段；缺失时前端有 fallback，
不会因为某份实验 JSON 还没生成就白屏。

## 三、架构设计页

页面：`frontend/src/views/architecture/index.vue`，侧边栏「设计文档 → 架构设计」。

新增/补强：

- **从整体到局部** L1 系统拓扑 → L2 六层结构 → L3 层内模块 → L4 代码地图；
- 六层每层补了 `modules`（关键模块）与 `tags`（技术栈）；
- 新增 **层间接口与通讯方式**：浏览器→主系统（HTTP/JSON、Sa-Token）、
  主系统→智能体（HTTP/JSON、X-Agent-Token、30s/120s）、
  智能体→语言模型（HTTPS/JSON）、智能体→向量模型、主系统→MySQL（JDBC/SQL）、
  浏览器→图表（本地渲染），并标注超时和代码位置；
- 保留拓扑图、一次审核四步链路、代码地图、性能实测。

## 四、需求设计页

页面：`frontend/src/views/design/requirements.vue`，侧边栏「设计文档 → 需求设计」。

- **角色 × 功能矩阵**：管理员/审核员/创作者 × 9 个模块，● 完整 / ◐ 部分 / — 无；
- **9 个功能模块**：认证与个人中心、用户与权限、内容创作、智能审核与人机协同、举报处理、
  跨平台适配、数据看板、评测与优化、系统说明；
- 每个模块卡片可打开抽屉，包含：子模块、关键流程、接口、代码位置、涉及数据表、
  核心代码片段、边界与细节；
- **三条核心链路**：投稿→审核→发布、选稿→适配→合规、登录→权限→接口；
- **八条关键设计判断**：三层权限、稿件状态机、两阶段 Agent、人机协同、内容哈希过期、
  失败降级、并行适配、角色化数据。

页面是静态内容，不查数据库；所有登录用户可见，不需要新增菜单权限。

## 六、第二轮：扩集与 C1/E2

- **评测集**：核心 28 + ToxiCN 200 + COLD 200 = 428 条；公开集只做二分类，规则召回只看核心集。
- **C1（紧凑 RAG）**：关键词限流 + 特异性排序 + 阈值 0.55 + 类别去重 + 召回安全阀；
  相对 C，token 1464→1178（-20%），规则召回 51%→62.5%，核心准确率 85.7%→92.9%，公开召回 58.5%→53.5%。
- **E2（B + 后置归因）**：B 判定，片段用规则示例词/领域词匹配回规则；核心准确率/召回与 B 相同
  （96.4%/91.7%），token 与 B 相同（952），但规则召回 47.9%，仍低于 C1/D；后置归因还需补强。
- **结论**：总体准确率 D 75.2% > C 73.4% > C1 72.4% > B 67.1% > E2 66.8%，但公开集占比大；
  核心集 B/E2 更强。生产默认暂保持 C，C1/E2 作为实验配置，不把“可审计”说成“更准”。
- 详细数据：`docs/实验-扩展集-C1-E2分析.md`。

## 七、已知取舍

- 评测页图表较多，小屏会退化为单列；数据明细仍保留表格，方便论文抄数；
- 人工评分全 5 分导致 Spearman 无定义，页面如实写"无定义"，不伪造相关性；
- 架构页的接口表是"当前实现"的契约，不是通用架构模板；改接口时要同步改页面；
- 实验单轮有波动，页面结论用方向性表述，不把 1–2 个百分点当稳定差异。
