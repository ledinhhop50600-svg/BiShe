## 二、适配评估的方法

**评测集**：4 篇稿件 × 3 个平台 = 12 个结果。

- #1 小户型收纳（201 字，正常）
- #2 平价护肤（163 字，正常）
- #8 减脂餐一周瘦十斤（101 字，夸大，已驳回）
- #16 全屋收纳长文（2102 字，压缩）
- 平台：小红书（1000 字上限）、公众号（长文）、抖音（口播脚本，1000 字上限）

**为什么直接调用 Agent，而不是主系统的 `/adapt`**：

1. 评测不应往演示库写适配记录；
2. 可以传确定性 `requestId`，复用 Agent 回放缓存，重复评测不重复花钱。

**指标**：

- 格式自检通过率（程序计算，确定性）；
- 长文压缩比（适配长度 / 源文长度）；
- 合规预检等级（复用审核规则库）；
- LLM 评分：风格符合度 / 信息保留度 / 可读性，1-5 分；
- 人工评分：同一套维度，填 `adaptation-human-sheet.csv`，后续算与 LLM 评分的 Spearman 相关。

**LLM 评分缓存**：key = 平台 + 适配标题 + 适配正文的 SHA-1。同一结果重复评测直接命中缓存，
保证数字稳定且不重复花钱。换 `--run-id` 会强制重新生成适配内容，缓存只在内容相同的时候命中。

## 三、结果（`paper-20261019-v2`，真实调用）

| 平台 | 格式通过率 | 长文 #16 压缩比 | LLM 风格 | LLM 保留 | LLM 可读 |
|---|---|---|---|---|---|
| 小红书 | 100%（4/4） | 0.38 | 4.00 | 4.50 | 4.75 |
| 微信公众号 | 100%（4/4） | 0.94 | 4.00 | 4.75 | 4.75 |
| 抖音 | 100%（4/4） | 0.42 | 4.00 | 4.50 | 4.50 |

- 总计 12/12 格式通过，139.5 秒，单次适配约 6 秒（含改写 + 合规预检两次模型调用）；
- 长文压缩：小红书 0.38、抖音 0.42（明显压缩），公众号 0.94（基本等长）—— 符合平台形态；
- 短文本适配会扩写（补充钩子/分段/平台化表达），所以"平均长度比"大于 1 是正常的，
  压缩效果要看长文那一列。

**必须如实写进论文的波动**：在另一批 `paper-20261019` 运行中，小红书 + 2102 字长文输出
**1111 字，超出 1000 字上限**，该批通过率为 11/12（91.7%）。说明长文压缩仍是弱项，
模型不总能遵守"目标为上限 85%"的约束。系统会给出明确警告，不会把超限结果当成通过；
这也说明"格式自检交给程序"是必要的。

**LLM 评分的问题**：分数集中在 4-5，区分度低（风格平均 4.0-4.25）。这不是"适配完美"的证据，
而是 LLM 评委偏宽松。论文里必须用人工评分对照，并报告一致性；不能只报 LLM 分数。

## 四、评测中心

页面 `/eval`（仅管理员，`eval:manage`）：

- **审核实验**：52 条评测集、4 方案总体指标、分层准确率、v3/v4 口径对照、结论；
- **适配评估**：通过率、分平台指标、长文压缩比、LLM 评分、未通过项；
- **演示运行**：按钮调用 `tools/eval_adaptation.py --run-id demo --out-dir docs/eval/demo`，
  结果写入 demo 目录，**不覆盖论文数据**；首次约 2-3 分钟，之后复用回放缓存约 25 秒；
- **复现方式**：直接给出各脚本命令。

**为什么页面不重算指标**：指标口径只能有一份。Java 重算一遍就可能与 Python 脚本不一致，
论文数据与页面数据对不上是答辩大忌。页面只读 JSON，计算都在脚本里。

**为什么用 ProcessBuilder 跑脚本**：本地单机项目，脚本已经过验证；固定命令、管理员权限、
10 分钟超时、单实例锁（并发只允许一个评测进程）。没有为"一键跑"再写一套 Java 评测逻辑。

## 五、踩到的坑

| 问题 | 原因 | 处理 |
|---|---|---|
| 回放运行的耗时覆盖了真实数据 | 同一 run-id 重跑全部命中回放，报告里的耗时变成回放查找时间 | 论文数据用新 `--run-id` 真实跑一次；评测中心的 demo 用独立目录，不覆盖论文数据 |
| LLM 评分重复花钱 | 每次重跑都重新调用评委 | `judge-cache.json` 按内容哈希缓存 |
| 报告里"平均长度比"看起来像越改越长 | 3 篇短文扩写把均值拉高 | 报告增加"长文 #16 压缩比"列，并说明短文本扩写是正常现象 |
| 页面一键跑会覆盖论文结果 | 脚本默认写 `docs/eval` | 增加 `--out-dir`，页面固定写 `docs/eval/demo` |

## 六、已知局限

1. 适配评估只有 4 篇稿件、3 个平台，样本量小，结论以方向性为主；
2. LLM 评分区分度低，人工评分尚未填写；
3. 合规预检复用审核规则库，平台专属规则仍不完整；
4. 审核实验只有 52 条，统计显著性有限；
5. 一键评测同步执行，期间页面一直 loading；后续可改为后台任务 + 轮询状态。
